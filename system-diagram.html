ollama-tiny-tasks — System Architecture

Pipeline orchestrator · Local LLM (Ollama) · SQLite · Next.js UI

Pipeline Stages (in order)
🏛
STAGE 0 Architect
Determines which output files to produce and what each is responsible for. Builds the file manifest — a list of {path, description, imports} entries that drive all downstream routing. Falls back to heuristic inference if parse fails.
Architect
Output: manifest saved to projects.fileManifest — e.g. Card.tsx (single card), KanbanColumn.tsx (column + input), App.tsx (root state)
Also: ContractDesigner produces shared TypeScript interfaces injected into every subsequent file
🧩
STAGE 1 Decompose
Project Manager splits the description into 3–5 epics (high-level user-facing features). Reviewer filters out unnecessary ones. Epics are stored as depth-1 tasks with status awaiting_approval.
ProjectManager Reviewer
Cap: MAX_EPICS = 4
Output: rows in tasks table, depth=1, status=awaiting_approval
📋
STAGE 2 Breakdown
Manager expands each epic into 2–3 concrete features (depth-2 tasks / leaves). Manager receives the full file manifest and must prefix each feature with [FileName.ext] to declare which file it belongs to. Prefix is stripped before storing.
Manager
Cap: MAX_SUBTASKS = 2 per epic · MAX_TASKS = 200 total
Dedup: Semantic similarity check removes near-duplicate features (Jaccard > 0.6)
Routing: [File.ext] prefix → priority-1 route; else keyword scoring; else round-robin
Output: depth-2 tasks, each with file_path assigned
🧪
STAGE 3 TDD — Generate Tests code files only
Test-writer produces a .test.tsx / .test.ts file for each output file. Tests are written before the implementation so they define the contract. Skipped for non-code files (markdown, JSON, etc.).
TestWriter
Framework: Vitest + @testing-library/react
Output: test files written to output/{id}/*.test.tsx
⚡
STAGE 4 Execute
One file at a time (build-order waves). For each file: a planner outlines the implementation, then a developer sequentially adds one feature per step. Each step reads the current file, adds one feature, validates, writes. Receives FILE ARCHITECTURE (manifest descriptions) and sibling export signatures so components know their role and what to import.
Developer Editor (patch) Cleaner (syntax) Summariser
Turn 1: "Output ONLY the FIRST atomic edit as a single SEARCH/REPLACE block" — prevents giant one-shot dumps
After each edit: TypeScript syntax check → semantic check (DOM lib, caps at 5 errors, ignores module-not-found noise)
Syntax fail: Cleaner → minimal retry → scaffold tactic → reframe tactic (up to MAX_RETRIES = 2)
Export signatures of completed siblings injected → import hints like import {"{ Card }"} from "./Card"
Waves: files with no imports run first; App.tsx (root) runs last
🔍
STAGE 5 QA
Runs the generated Vitest tests. On failure: iterative-QA loop finds one bug, fixes it, re-runs. Holistic reviewer checks structural consistency across files. Judge decides if output is good enough to skip expensive passes.
TestQA (vitest) IterativeQA HolisticReviewer Judge
IterativeQA loop: "find one bug → fix → re-run" (max iterations)
Judge verdict: proceed | warn | skip_vitest
Skip condition: all tests pass on first run → holistic review + improvement skipped
💬
STAGE 6 Feedback Pass user-triggered
User submits feedback via the UI. FeedbackPlanner creates targeted fix tasks. FeedbackEditor applies SEARCH/REPLACE patches. QA re-runs after. Can target specific files or the whole project.
FeedbackPlanner FeedbackEditor QA (re-run)

File Routing Priority

How a feature task is assigned to a file (assignFileForTask)

P1[FileName.ext] prefix in task title — set by Manager. Direct, case-insensitive manifest lookup.
P2Explicit filePath column already set on the task row.
P3Keyword scoring — Jaccard overlap between task words and manifest file descriptions.
P4Round-robin cursor — tiebreak when all files score equally.

Execute Recovery Chain

What happens when a DEV step produces invalid code

1. Syntax check (TS compiler API) — errors appended to next prompt
2. Semantic check (getSemanticDiagnostics, DOM lib) — caps at 5, ignores import noise
3. Cleaner — targeted fix prompt with the error
4. Minimal retry — stripped-down re-ask
5. Scaffold tactic — rewrite from scaffold up
6. Reframe tactic — rephrased task description
7. Mark stuck — task paused after MAX_RETRIES = 2
